### Reproducibility and claim safety

- Displayed figures are formatted from source JSON/text at render time.
- Beat 4 is 9 seconds of the evidence card plus 20 seconds of literal output
  derived from an actual `make demo` PTY run.
- Capture playback normalizes line-reveal pauses and holds the final frame for
  legibility; transcript text is unchanged.
- The capture bundle retains raw ANSI bytes, cleaned text, timestamped/base64
  PTY events, GIF, receipt, and validated `SHA256SUMS`.
- Capture runs with an exact environment allowlist, isolated `HOME`/`TMPDIR`,
  timeout, owned process-group termination, and transcript/event/GIF limits.
- Receipt validation rejects absolute paths, traversal, symlinks, unknown keys
  or filenames, stale branch/HEAD/archive/driver state, changed executable
  paths, altered exit contracts, and hash mismatches.
- The renderer asserts the known run ID and claim-boundary booleans before it
  creates any frame.
- It refuses stale Spark symbol counts or changed L3 repetition results.
- The story order is validated explicitly.
- Source SHA-256 hashes are recorded beside the final media receipt.
- `--tts none` removes the only host-specific step while preserving the fixed
  timeline, silent AAC track, and authored SRT.
- No generated presenter footage, stock footage, music, staged terminal
  output, or claimed CI state is introduced by this cut.

### What the old pipeline did well

- Six deterministic 15-second scenes: 2,700 frames = 90 seconds.
- `story.json`, `cues.json`, and `layout.json` separated claims, captions, and
  measured presenter clearance from composition code.
- The 2026-08-08 recut removed the stale race and reused only two unchanged
  presenter clips.

  were already production-shaped.
- The old MP4 itself is web-playable and under the contest cap.
- The historical layout solver measured scene 02's required correction at
  `1.21`× zoom; that registered layout value remains preserved here even
  though the current evidence-card cut has no presenter-occlusion problem.

### Why it is no longer the final contest story

1. The cost card appears before the L3 executed-kernel explanation, so the
   evidence chain is out of the required order.
2. It contains no automated Arm64 readiness beat and cannot cite GitHub Actions
   run `31294460364`.
3. Its close predates the current explicit `candidateOnly` /
   `productionReady:false` boundary.
4. It does not constrain the Pro 6000 30B campaign to non-Arm systems evidence.
5. Reproduction depends on an external generated-presenter workspace,
   downloaded clips, layout state, and preserved `node_modules`, none of which
   are in this repository.
6. The package metadata still carries an old `ledgerlens` project name and its
   `npm render` script references a `src/` layout that does not match the
   preserved top-level files. The manual `npx remotion render Polygraph ...`
   command works, but the package script is not a reliable single-command
   receipt.
7. The prior full-range `yuvj420p` output is widely playable, but the current
   renderer requests standard limited-range `yuv420p` explicitly.

The prior render remains valid historical provenance. It is not deleted,
rewritten, or presented as the current submission cut. The repository-native
hybrid MP4 documented above is the only authoritative submission cut.
